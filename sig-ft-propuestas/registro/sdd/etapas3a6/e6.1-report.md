### E. Lançador do macOS
- `SIG-FT.command` (clique duplo no Finder) faz `source` de `scripts/_bootstrap_venv.sh` e chama
  `sigft_bootstrap`; depois roda `frontend.py` a partir da raiz, com o python do venv.
- `scripts/_bootstrap_venv.sh` só DEFINE funções (o `source` não faz nada sozinho — é o que deixa os
  testes chamarem cada uma). Mesmo comportamento do `.bat` no que vale no Mac:
  - Python 3.10+: procura `python3.12 python3.13 python3.11 python3.10 python3` e os caminhos do
    python.org/Homebrew; pula o `/usr/bin/python3` da Apple quando não há Command Line Tools (ele
    abriria a janela de instalação em vez de rodar). Sem Python: mensagem com
    https://www.python.org/downloads/macos/;
  - venv: `SIGFT_VENV` > `<raiz>/.venv` > `~/Library/Application Support/SIG-FT/venv` > novo — na
    raiz, ou em Application Support se a pasta for de iCloud Drive (`Library/Mobile Documents`),
    `Library/CloudStorage` (onde o macOS 12.3+ põe OneDrive/Dropbox/Google Drive/Box), OneDrive,
    Dropbox, Google Drive ou Box (caminho dado e físico), mais uma heurística para o iCloud
    "Mesa e Documentos" (o link que o iCloud Drive ganha para `~/Desktop`/`~/Documents`);
  - `requirements.txt` só quando muda: carimbo `.sigft-requirements.stamp` com o SHA-256
    (`shasum`, `sha256sum` ou `cksum`), gravado só depois de um pip que deu certo;
    `requirements-dev.txt` com `SIGFT_DEV=1`; mesmos argumentos de pip do `.bat`
    (`SIGFT_PIP_ARGS` > `pip_corporativo.txt` > padrão);
  - navegador do Playwright uma vez (carimbo), carimba sem baixar se o Chromium já abre, nunca
    derruba a abertura, `NODE_EXTRA_CA_CERTS` a partir de `SSL_CERT_FILE`;
  - erro em qualquer passo: "[SIG-FT] Encerrado com erro..." e `read` ("Pressione Enter para
    fechar esta janela.") — o `pause` do `.bat`; saída 1.
  - Escrito para o bash 3.2 do macOS (sem `${x,,}`, `mapfile`, vetor associativo).
- Bit de execução gravado no git (`git update-index --chmod=+x`): `100755` nos dois.

## Desvios deliberados (e o porquê)
1. `TelaNaoMigrada` dizia "Use a versão atual (python frontend.py)": depois do corte esse comando
   abre a própria Qt. Agora diz `python frontend.py --ctk`. (O texto igual da Home sumiu sozinho com
   a Home completa do 748d3a4.)
2. `SIG-FT.command` repassa os argumentos (`"$@"`): no Terminal, `./SIG-FT.command --ctk` abre a
   antiga. O `SIG-FT.bat` NÃO repassa (não mexi: o brief e o desenho dizem que ele não muda) — no
   Windows o `--ctk` é pela linha de comando.
3. README: além do "botão direito → Abrir", uma frase para o macOS 15+, onde a Apple tirou esse
   atalho do Gatekeeper (Ajustes do Sistema → Privacidade e Segurança → Abrir Mesmo Assim). É a
   mesma instrução de primeira abertura, só completa.
4. Relatório do smoke com uma linha por tela (OK/FALHOU), a linha das bloqueadas e a pilha de cada
   tela quebrada — além do mínimo pedido (nome + motivo), porque é o que poupa um build por
   hipótese.
5. A dica de erro do pip no Mac acrescenta "o PySide6 exige o macOS 12 ou mais novo" (medido nas
   wheels do PyPI): no macOS 11 o pip falharia sem pista.
6. Nada foi escrito em `docs/refatoracao/PENDENCIAS.md` nem no mural do `CLAUDE.md` (o aviso da
   troca de UI é da E6.3); os achados estão nas preocupações abaixo.
